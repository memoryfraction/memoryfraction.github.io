📊 Data source & granularity 数据源与粒度

  • NUGET public APIs expose lifetime cumulative downloads only (per package / per version). The official v3 stats time-series API is gone (all endpoints return 404 — verified 2026-08; no Stats resource in the v3 service index).
  • Finest granularity = DAY: a GitHub Actions workflow snapshots the cumulative counters once per day (11:30 UTC); a day's downloads = difference between consecutive snapshots.
  • Week / Month views are calendar aggregations (ISO week / calendar month) of the daily deltas — derived, not native data.
  • Sub-day (hourly) precision is not possible — the data source does not provide it.
  • NuGet's counters update with a lag (hours), so the latest day may be under-counted until the next snapshot.
  • NuGet 公开 API 只提供累计总下载量（按包 / 按版本）。官方 v3 统计时间序列接口已下线（2026-08 实测全部 404，v3 service index 中也没有 Stats 资源）。
  • 最细粒度 = 天：GitHub Actions 每天 11:30 UTC 快照一次累计计数，某天的下载量 = 相邻两次快照的差值。
  • 周 / 月视图 = 按日历周（ISO）/ 日历月对日增量做的聚合，属于推导值，不是 NuGet 原生数据。
  • 小时级更细的粒度：数据源不支持。
  • NuGet 计数器本身有数小时延迟，最近一天可能要等下一次快照才完整。
